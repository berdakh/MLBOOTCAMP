# Data

`raw/` holds the TaskFlow extract used throughout Part I of the book: four
gzipped CSV files, treated as an immutable export from a production database.
TaskFlow is a synthetic subscription-software company whose customers may
cancel ("churn"); [Chapter 2](../part1-foundations/ch02-reproducible-project/README.md)
introduces the problem.

| File | Rows | One row per |
|---|---:|---|
| `customers.csv.gz` | 5,000 | account, *as exported today* |
| `usage_weekly.csv.gz` | 210,625 | account × completed week with activity (plus planted duplicates) |
| `invoices.csv.gz` | 55,570 | monthly invoice, paid or failed |
| `tickets.csv.gz` | 22,354 | support ticket |

**The data is synthetic.** It was generated by `src/churnlab/data.py`
(`generate()`, default `GeneratorConfig`) and written with
`python tools/make_dataset.py`. The SHA-256 of each file is pinned in
`churnlab.data.RAW_SHA256`, and `tests/test_churnlab.py` fails if a file
changes. Do not edit these files by hand; regenerate them and update the
hashes in the same commit.

Defects were planted in the data deliberately, and
[Chapter 3](../part1-foundations/ch03-data-acquisition-and-validation/README.md)
asks the reader to find them. They are listed in that chapter's
[solutions](../part1-foundations/ch03-data-acquisition-and-validation/solutions.md);
read the list only after completing the lab.

Part II does not use this folder: its ShopStream data set is generated by
`src/shoprank` into the artifact directory when a lab first needs it.
